# arc5 Email Archive (IMAP, Gmail) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Archive mailboxes over IMAP, Gmail first: log in with an app password from the Sources page, archive the chosen folders (each message once), turn HTML-only mail into good text, keep the original of every message, capture new mail and deletions, and show mail in the approved mail layout with search.

**Architecture:** `internal/mail` parses messages (go-message), converts HTML to text (x/net/html) and names threads; it is pure and knows nothing of storage or IMAP. The archive gains the `thread` chat kind, subjects, addresses, folders and folder membership, and keeps each original in the media store. `internal/connector/email` talks IMAP through go-imap v2 behind a narrow `client` interface that the tests fake; it writes through `connector.MailSink`, an extension of `Sink` that the runner's sink implements (so the Telegram connector and its fakes are untouched). The web layer gains the mail layout, the thread view and the original's download.

**Tech Stack:** Go 1.26, `github.com/emersion/go-imap/v2` v2.0.0-beta.8 (pinned), `github.com/emersion/go-message` v0.18.2, `golang.org/x/net/html`, SQLite (modernc), `html/template`, Stimulus.

**Spec:** `docs/superpowers/specs/2026-10-13-email-archive-design.md` (the revision of 2026-10-13 with Gmail and HTML-only mail), on top of `2026-10-12-message-archive-design.md`.

**How this plan was written.** The owner said "start working on email", "I need Gmail support for sure" and "make sure html only emails are parsed to text correctly", while testing Telegram with the main session. Like the Telegram plan, it is written to be executed straight away: each task gives the interfaces it produces and consumes and the tests to write first; the code is in the task's commit. Decisions taken here are listed for the owner.

## Decisions for the owner to confirm

The spec's ten decisions, plus:

1. **The demo gains a mailbox** ("Home mail", a hidden `demo-mail` connector) with the mockups' conversations, one of them HTML-only, built from real MIME through the same parser the connector uses.
2. **Recipients are people too:** every From, To and Cc address becomes a sender row, so "Chats and people" finds anyone the owner corresponded with by name or address. "Everything from this person" still lists only what they sent.
3. **The folder filters are links** styled as the mockup's checkboxes, so they work without script.
4. **"Fetch now" on a large mail attachment** is answered from the kept original, without contacting the server, by the connector's own goroutine.

## Global Constraints

- No cgo. `internal/archive` stays the only database writer.
- Nothing in `internal/connector/telegram` changes.
- IMAP fetches use `BODY.PEEK` only; the connector never sends `STORE`, `COPY`, `MOVE`, `EXPUNGE`, `APPEND`, `DELETE` or `CREATE` (the `client` interface has no such method, and a test fails if the go-imap adapter's source names them).
- Mail HTML is never rendered: text only, through `html/template` escaping.
- Durability: a folder's checkpoint is written only after every message of its batch is stored; originals and attachments are synced files.
- Every task ends with `gofmt -l internal cmd` printing nothing and `go vet ./... && go test -race -count=1 -timeout 180s ./...` passing.

## Review Focus

1. **Never marks mail as read or changes the mailbox** (the client interface, the adapter, the memserver test).
2. **Deletion rule:** a message is marked deleted only when gone from every folder it was filed in; a move between archived folders within one cycle never marks it; a message seen again is un-deleted.
3. **Checkpoints never pass unstored mail**, and a UIDVALIDITY change re-reads without duplicating.
4. **HTML-to-text output** has no CSS, script, hidden preheader or tracking-pixel residue, and keeps paragraphs, lists, links and quotes.
5. **Hostile mail** (HTML, header injection in names, odd file names) reaches pages only as escaped text; the original is served as a sandboxed download.
6. **The table rebuild of `chats`** keeps every row, ID and index, with foreign keys checked before commit.

### Task 1: Mail messages in the archive

**Produces:**
- `model.ChatThread ChatKind = "thread"` (valid; archived by default).
- `type model.AddressRole string` (`AddrFrom`, `AddrTo`, `AddrCc`, `AddrBcc`, `AddrReplyTo`); `type model.Address struct { Role AddressRole; Name, Address string }`.
- `model.Message.Subject string`, `Addresses []model.Address`, `Original []byte` (the message as received; mail only).
- Migration `0006_mail.sql`, whose first line `-- arc5: foreign keys off` makes `migrate` run it on one pinned connection with `PRAGMA foreign_keys = OFF`, check `PRAGMA foreign_key_check` is empty before committing, and switch them on again. It rebuilds `chats` with `thread` in the kind check (same columns, IDs and index), and adds `accounts.address`, `messages.subject`, `messages.original_sha256`, `message_addresses`, `folders`, `message_folders` as in spec section 4.
- `UpsertMessage`: stores the subject; the addresses once (the first copy's); the original as a media-store file (synced) named by `original_sha256`, also filled in for a stored message that has none. The index document is the subject, the text and the file names.

**Tests first:** `TestMigrationRebuildsChats` (a database at version 5 with chats, messages and avatars migrates; rows, IDs, the avatar index and foreign keys survive; a `thread` chat is accepted); `TestMailMessageStored` (subject, addresses in order, original file on disk with the hash, second upsert changes nothing, a stored message without original gets one); `TestSubjectIsSearchable` via the index row; the migration count test updated.

### Task 2: Folders and membership in the archive

**Produces** (`internal/archive/folders.go`):
- `type model.FolderRole string` (`inbox`, `sent`, `all`, `drafts`, `junk`, `trash`, `flagged`, `important`, `other`) with `Valid()`; `type model.Folder struct { SourceID, Name string; Role FolderRole; ArchiveByDefault bool }`.
- `(*Store).UpsertFolder(accountID, model.Folder) error` (first sight: archived per `ArchiveByDefault`; later: name and role refreshed, the owner's choice kept).
- `FolderArchived(accountID, folderSourceID) (bool, error)` (unknown: false).
- `type FolderEntry struct { ID int64; SourceID, Name string; Role model.FolderRole; Archived bool; Messages int }`; `AccountFolders(accountID) ([]FolderEntry, error)` ordered Inbox, Sent, All, others by name, then Flagged, Important, Drafts, Junk, Trash.
- `SetFoldersArchived(accountID, map[int64]bool) error`.
- `FileInFolder(accountID, folderSourceID string, uid uint32, chatSourceID, messageSourceID string) error`: membership present with this UID; clears the message's `deleted_at`. Unknown folder or message: `ErrNotFound`.
- `FolderUIDs(accountID, folderSourceID) ([]uint32, error)`: present memberships with a known UID, ascending.
- `LeaveFolder(accountID, folderSourceID string, uids []uint32) error`: sets `gone_at`; a message with no present membership left gets `deleted_at` (first time only).
- `ResetFolder(accountID, folderSourceID) error`: forgets the folder's UIDs (memberships stay present).
- `SetAccountAddress(accountID, address) error`; `Account.Address`.
- `Original(accountID, chatSourceID, messageSourceID string) (io.ReadCloser, error)` (`ErrNotFound` without one).

**Tests first:** `TestFolders` (defaults, owner's choice kept, ordering, counts); `TestMembershipAndDeletion` (in two folders, gone from one: not deleted; gone from both: deleted once; filed again: un-deleted; a UID of another folder untouched); `TestResetFolder`; `TestOriginal`; `TestAccountAddress`.

### Task 3: Reading mail

**Produces** (`internal/archive/mail.go`):
- `type ThreadFilter struct { FolderID int64; Role model.FolderRole; Files, Deleted bool }` (no folder and no role: every thread).
- `type ThreadSummary struct { ID, AccountID int64; Title string; Messages int; FirstAt, LastAt time.Time; Snippet string; Person, PersonAddress string; Others []string; WithOwner, LastOutgoing, HasFiles, AllDeleted bool }`: Person is the latest sender who is not the owner (else the first recipient of the latest message), Others the names of the other non-owner senders.
- `(*Store).Threads(accountIDs []int64, f ThreadFilter, limit, offset int) ([]ThreadSummary, error)`, newest first; a thread is in a folder when any of its messages was filed there (gone or not), so deleted mail stays listed.
- `type MailMessage struct { ID int64; Subject, Text string; SentAt, DeletedAt time.Time; Outgoing bool; From model.Address; To, Cc []model.Address; Attachments []StoredAttachment; HasOriginal bool }`; `ThreadMessages(chatID int64, limit int) ([]MailMessage, bool, error)` oldest first (the newest `limit`).
- `OriginalFile(messageID int64) (path string, subject string, err error)`.

**Tests first:** `TestThreadsByFolder`, `TestThreadFilters`, `TestThreadPeople` (person, others, and you, a thread only from the owner), `TestThreadMessages`.

### Task 4: Parsing mail

**Produces** (`internal/mail`):
- `type Part struct { FileName, MimeType, ContentID string; Inline bool; Data []byte }`.
- `type Parsed struct { MessageID string; References []string; InReplyTo, Subject string; Date time.Time; Addresses []model.Address; Text string; Parts []Part; Broken bool }`.
- `Parse(raw []byte) Parsed` (never fails: unreadable mail gives `Broken` and the text "This message could not be read"); the text is the plain part, or the HTML converted (task 5) when there is no plain part or it only says to view the HTML; `format=flowed` joined; CRLF to LF.
- `NormalizeID(string) string`; `Identity(p Parsed, raw []byte) string` (Message-ID, else `sha256:`…); `ThreadRoot(p Parsed, known func(messageID string) (thread string, ok bool)) string` (spec section 5, returns `thread:<id>`); `CleanSubject(string) string`; `AttachmentKind(mimeType) model.AttachmentKind`.
- `(p Parsed) Message(chatSourceID, sourceID string, own func(address string) bool, received time.Time) model.Message`: subject, addresses, text, attachments (kind, name, type, size), sender (lower-cased From), outgoing, date (the received time when the Date header is missing).

**Tests first** with fixtures in `testdata/mime/`: plain, multipart/alternative, mixed with alternative and attachment, related with inline image, KOI8-R, Shift_JIS, quoted-printable, base64, RFC 2047 names and subject, winmail.dat as a file, a message/rfc822 attachment, no Message-ID, broken MIME, format=flowed; `TestThreadRoot`, `TestCleanSubject`, `TestIdentity`.

### Task 5: HTML to text

**Produces:** `HTMLText(body []byte, mimeCharset string) string` following spec section 6 exactly, on the `golang.org/x/net/html` parser (the tree, so implied and broken tags are handled as a browser does).

**Tests first:** golden files `testdata/html/<name>.html` → `<name>.txt` for: newsletter (table layout, preheader, tracking pixel, social icons, unsubscribe), receipt (items table), outlook (mso conditionals, `<o:p>`, `MsoNormal`), gmail reply (`div dir=ltr`, `gmail_quote`), apple reply (`blockquote type=cite`), entities (`&nbsp;` runs, `&zwnj;`, `&amp;`), breaks (`<br>` runs), lists (nested `ol`/`ul`, `start`), headings and `pre`, a Windows-1251 page with only `<meta charset>`, links of every kind. `TestHTMLHasNoResidue` over the corpus (no `{`, `@media`, `<`, `display:`, tracking hosts). Golden files are written by hand from what a reader sees in a browser, then compared; `-update` is not offered.

### Task 10: The IMAP client

**Produces** (`internal/connector/email/client.go`):
```go
type mailbox struct { Name string; Attrs []string } // attributes lower-cased, such as `\all`
type selected struct { UIDValidity, UIDNext, Messages uint32 }
type header struct { UID uint32; Size int64; Received time.Time; MessageID string }
type client interface {
    List(ctx) ([]mailbox, error)          // selectable folders, with SPECIAL-USE when offered
    Select(ctx, name string) (selected, error) // read-only (EXAMINE)
    Search(ctx, from, to uint32, since time.Time) ([]uint32, error) // UIDs in [from, to], to 0 = *
    Headers(ctx, uids []uint32) ([]header, error) // BODY.PEEK[HEADER.FIELDS (MESSAGE-ID)]
    Fetch(ctx, uid uint32, headersOnly bool) ([]byte, error) // BODY.PEEK[] or [HEADER]
    Idle(ctx, wait time.Duration) error   // until the server reports a change, or wait
    Close() error
}
```
`dial(ctx, account) (client, error)`: TLS on 993, STARTTLS otherwise, LOGIN; a refused login is `errLoginRefused`. Folders are opened with EXAMINE, so even a server that ignored PEEK could not set `\Seen`.

**Tests first** against `imapmemserver` on a local listener: list with special use, examine, search by range and date, headers, fetch whole and headers only, IDLE wakes on a new message, expunge seen as a lower count, `\Seen` never set; the source-scan test for forbidden commands.
